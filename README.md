# GAIA 大地 — water, energy and agriculture for Tunisian farms

GAIA is a Kizuna Challenge 2026 prototype (Tunisia × Japan). It answers one question for a farm plot:
**which practices fit this land, how much water does the crop really need, and how much solar power does it take to pump only that?**

It pairs Tunisian practices (jessour, oases, olive groves) with Japanese ones (tanada terraces, satoyama,
solar sharing, kaizen), checks each one against the plot's real conditions, and refuses to recommend what does not fit.

## The nexus in one line

Crop water need (FAO-56) → pumping energy → solar pump size → a monthly water quota.
The pump is sized to the crop, not to the aquifer, so solar power does not become a reason to over-pump groundwater.

## Run it

The website needs no build and no install. Open `index.html` in a browser, or serve the folder:

```
npx serve .
```

The optional API is in [`backend/`](backend/README.md) (FastAPI):

```
cd backend
pip install -r requirements.txt
uvicorn gaia.main:app --reload      # http://127.0.0.1:8000/docs
pytest -q
```

Everything in the website works without this server, except two optional extras: the online Pl@ntNet check in
Plant health (an offline Pl@ntNet model now runs in the browser without it) and the server-side language models of the AI Lab and the Farm Agent (the Lab can also run a free model inside the browser). For Pl@ntNet, put `PLANTNET_API_KEY=...` in `backend/.env`
(never commit it), start the server as above, and reload the page. **Free key:** create an account at
[my.plantnet.org](https://my.plantnet.org), open *Your API key* (500 identifications a day for free) and paste it after `PLANTNET_API_KEY=`. The page finds the server on port 8000 or 8765
and says why the check is unavailable when it is not (server not running, no key, key refused, network).

## Soil data

The Land DNA reads soil in this order (the SoilGrids REST API was paused by ISRIC in 2024–25 and answers again since November 2026):

1. `soilEndpoint` in `js/gaia-core.js`, if you serve downloaded SoilGrids rasters for Tunisia;
2. the SoilGrids REST API (250 m, one retry; if it fails it is skipped for 30 minutes);
3. `js/soil-tn.js`: typical topsoil values (texture, clay, organic carbon, 0–30 cm) for 21 Tunisian agro-ecological
   zones, compiled as orders of magnitude from HWSD v2 (FAO/IIASA) and SoilGrids 2.0. These are shown with
   confidence "low" and the zone name, never as a measurement of the parcel. A soil analysis replaces them.

## Farm Agent: an AI that acts, not only answers

The agent has three brains, best first, and always shows which one is working:

1. **A language model with native tool calling**, through the GAIA server (`POST /agent/step`): Claude, Groq (free key),
   OpenRouter, Hugging Face or Ollama, configured exactly like the AI Lab below. The model decides which tools to call,
   reads the results, investigates risks with more calls, and stops when it can write the plan. The loop runs in the
   browser because the tools are GAIA's JavaScript modules working on the farmer's saved plot; the server only relays
   one reasoning step at a time, so no key ever reaches the browser.
2. **GAIA's planner + the free in-browser model** (Qwen2.5 1.5B, WebGPU): the planner runs the tools, the small model
   rewrites the plan without adding numbers.
3. **GAIA's planner alone**: offline, no key, deterministic. It parses the goal (place, crop, area, well depth, solar,
   aquifer), runs the tools and writes the plan from rules on their results.

Numbers the model writes that appear in no tool result are highlighted. Disease-risk rules (olive peacock spot, olive
fly, grape downy and powdery mildew, tomato/potato late blight with the Hutton criteria, citrus Alternaria, date-palm
heat) run on the hourly Open-Meteo forecast and cite their source; they flag weather that favours an infection, they do
not diagnose it.

## Crop vigour from space (Sentinel-2 NDVI)

`js/ndvi.js` finds the Sentinel-2 L2A scenes over the plot for the last 12 months (Element 84 Earth Search STAC, cloud
cover < 30 %), reads a small window of the red, near-infrared and scene-classification bands straight from the
cloud-optimised GeoTIFFs on AWS Open Data (HTTP range requests, geotiff.js), drops cloud, shadow and water pixels, and
returns the NDVI series, the 12-month median, the 90-day trend and any sudden drop. Free, no key, about 10 s, cached
4 days. Shown in Land Intelligence and used by the Farm Agent.

## AI Lab: a real language model (free options first)

Every question first gets GAIA's rule-based answer (records + Land DNA + verdicts). A language model then writes
the answer from that evidence and the last turns of the conversation; the rule-based sections stay one click below,
and any figure the model writes that is not in the evidence is highlighted. The Lab uses the first source that works:

| Source | Cost | How |
|---|---|---|
| Free model **inside the browser** (Qwen2.5 1.5B via WebLLM) | free, no key, no server | click *Turn on the free model* in the AI Lab (needs WebGPU: recent Chrome/Edge; ~1 GB downloaded once, then cached) |
| **Ollama** on the same computer | free, offline | install Ollama, `ollama pull qwen2.5:3b`, start the GAIA server: it finds Ollama by itself |
| **Groq** | free key (rate-limited) | `backend/.env`: `GAIA_LLM_PROVIDER=groq` and `GAIA_LLM_API_KEY=gsk_...` (key from console.groq.com) |
| **Hugging Face** / **OpenRouter** | free token / free models | `GAIA_LLM_PROVIDER=huggingface` (or `openrouter`) and `GAIA_LLM_API_KEY=...` |
| **Claude** | paid key | `ANTHROPIC_API_KEY=...` |

Start the server with `cd backend && uvicorn gaia.main:app --reload`.

**Sharing with friends.** Each browser looks for the server on its own computer (localhost), so a friend who only
opens the site gets the offline planner. To share your AI: start the server with
`uvicorn gaia.main:app --host 0.0.0.0 --port 8000`, serve the site (`npx serve .`) and have friends on the same Wi-Fi open
`http://YOUR-IP:3000/agent.html`: the pages then use the server on the same computer. Or add
`?server=http://YOUR-IP:8000` to any page URL (remembered; `?server=off` forgets it). An `https://` site cannot call an
`http://` server: deploy the backend behind https and set `assistantEndpoint`. On localhost the Lab finds it on port 8000 or
8765; elsewhere set `window.GAIA_CONFIG = { assistantEndpoint: 'https://your-server/assistant' }` before
`js/gaia-core.js`. Never commit a key: `backend/.env` is git-ignored.

## Plant health

The plant check never shows a diagnosis it did not compute.

1. The photo quality check (resolution, light, sharpness, share of leaf) always runs in the browser.
2. Tree and disease recognition run only when a model is installed: ONNX files plus a `manifest.json`
   in `models/gaia-vision/` for the website, or in `backend/models/gaia-vision/` (or `GAIA_MODEL_DIR`) for the API.
   The manifest sets the classes, the calibration temperature, the threshold under which GAIA says
   "I'm not sure", and the expert-validated advice cards. `health.html` shows an example manifest.
3. Without a model, the page says the model is not connected, and `POST /diagnose` answers `503 model_not_loaded`.
   With a model, `POST /diagnose` returns `ok`, `unsure`, `unsupported_tree` or `no_disease_model`.

Shipped models (details and honest test numbers in `ml/gaia-vision/TRAINING_REPORT.md`):

- **v3** (EfficientNet-B0): stage 1 finds the plant, stage 2 the disease for olive, date palm, citrus, tomato and pepper.
- **v4** (`gaia-vision-v4-pn.onnx`, 20 MB): Pl@ntNet's open MobileNetV4 (PlantCLEF 2024, 7,806 species, Apache-2.0)
  with GAIA disease heads for potato and grape. Same file also gives the species, **offline and without any key**.
- **Fusion**: when Pl@ntNet is confident about another plant than stage 1, it routes the photo to that plant's
  disease model. On field photos, plant identification rises from 59% to 80% (potato 28% → 70%).

The online Pl@ntNet API is optional (better on rare species): create a free account on my.plantnet.org, copy
"Your API key" (500 identifications a day) and put `PLANTNET_API_KEY=...` in `backend/.env`.

## Honest by design

- Every number shown is computed from a source or labelled as a simulation or a demonstration value.
- The four community profiles are illustrative scenarios, not real users.
- The sign-in page is a front-end mockup: nothing is sent or stored.
- Kaizen corrections stay on the device unless `feedbackEndpoint` is set in `js/gaia-core.js`.

## Design notes

Palette tokens are in `styles.css` (`--butter`, `--cream`, `--sage`, `--olive`, `--terracotta`, `--forest`…).
Use the `-deep` variants for text, because the base tones don't reach 4.5:1 contrast on cream.
Pages include a skip link, real buttons and labels, 44px touch targets and a `prefers-reduced-motion` path.
